1. Project Overview

The current credential management system in n8n requires users to manually navigate external documentation, generate API keys, and copy-paste sensitive information. This creates friction, increases error rates, and intimidates non-technical users.

🎯

Core Objective

Enable "just-in-time" credential creation directly within the node configuration interface, eliminating context switching.

🔐

OAuth2 First

Prioritize OAuth2 for all supported services, providing a secure "Sign in with [Service]" experience.

⚡

Zero Configuration

Users should never need to create OAuth clients, manage redirect URIs, or handle tokens manually.

Problem Statement

Current issues with the existing system:

  • High Friction: Users must leave n8n to find API keys
  • Error Prone: Manual copy-paste leads to mistakes
  • Security Risk: Users see and handle sensitive tokens
  • Poor UX: Intimidating for non-technical users
  • Context Loss: Users lose focus during workflow creation

2. User Experience Flow

1

Add Node to Canvas

User drags a service node (e.g., Google Sheets, Slack, HubSpot) onto the n8n workflow canvas.

2

Open Node Properties

User clicks on the node to open the properties panel. The credential field is empty and shows a prominent "Connect [Service] Account" button.

3

Initiate OAuth Flow

User clicks the connect button. A secure pop-up window opens to the service's official OAuth login page (e.g., accounts.google.com).

4

Authenticate & Authorize

User logs in with their existing account and grants n8n permission to access their data through the service's standard consent screen.

5

Automatic Completion

Pop-up closes automatically. The credential field now shows "Connected: user@example.com" and the node is ready for configuration.

🔧 Behind the Scenes

While the user experiences a simple "click to connect" flow, the system handles OAuth token exchange, secure storage, and automatic refresh token management completely transparently.

4. Technical Implementation

OAuth2 Flow Architecture

// Simplified OAuth flow implementation async function initiateOAuth(service, nodeId) { // Generate secure state parameter const state = generateSecureState(nodeId); // Build OAuth URL with service-specific parameters const authUrl = buildOAuthUrl(service, { client_id: getServiceClientId(service), redirect_uri: getCallbackUrl(), scope: getRequiredScopes(service), state: state, response_type: 'code', access_type: 'offline' }); // Open secure popup window const popup = window.open(authUrl, 'oauth', 'width=500,height=600'); // Listen for completion return new Promise((resolve, reject) => { const messageHandler = (event) => { if (event.origin === getCallbackOrigin()) { if (event.data.success) { resolve(event.data.credential); } else { reject(event.data.error); } popup.close(); window.removeEventListener('message', messageHandler); } }; window.addEventListener('message', messageHandler); }); }

Backend Integration Points

🔗 API Endpoints Required

  • POST /api/etf/oauth/initiate - Start OAuth flow
  • GET /api/etf/oauth/callback - Handle OAuth callback
  • POST /api/etf/credentials/create - Store encrypted credentials
  • POST /api/etf/credentials/test - Validate credential access
  • DELETE /api/etf/credentials/:id - Remove credentials

5. Security Considerations

🔒 Critical Security Requirements

All authentication tokens must be encrypted at rest and in transit. The system must implement proper token refresh logic and handle credential expiration gracefully.

🔐

Token Encryption

All OAuth tokens encrypted using AES-256 before storage in n8n's credential vault.

🔄

Automatic Refresh

Background token refresh ensures credentials remain valid without user intervention.

🛡️

Secure State Management

CSRF protection through cryptographically secure state parameters and origin validation.

Privacy & Compliance

  • Minimal Scope Requests: Only request necessary permissions for each service
  • User Transparency: Clear consent screens showing exactly what data will be accessed
  • Credential Isolation: Each client's credentials are completely isolated and encrypted separately
  • Audit Trail: Log all credential creation, usage, and deletion events
  • Revocation Support: Users can revoke access at any time through the service provider
